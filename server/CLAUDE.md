# server/

> **Draft doc.** Initial orientation pass, not exhaustive.

FastAPI API backed by PostgreSQL 16, accessed through SQLAlchemy 2.x (sync, psycopg2) with Alembic migrations. Python 3.12. Replaced an earlier NestJS + MySQL skeleton that was never built out.

## Environment

- Dependencies live in a local virtualenv at `server/.venv` (gitignored). Create it with `python3 -m venv .venv` and install with `.venv/bin/pip install -r requirements-dev.txt`.
- A venv embeds absolute paths, so it breaks if the repo folder is moved — delete and recreate it rather than debugging it.
- `requirements.txt` holds runtime deps only (what the Docker image installs); `requirements-dev.txt` adds pytest, httpx2, and ruff on top of it.
- Root git hooks call `server/.venv/bin/ruff` and `server/.venv/bin/pytest` directly, so the venv must exist at that path.

## Common commands

Run from `server/` (imports resolve from here, e.g. `app.core.config`):

```bash
docker compose up -d                  # local Postgres (app-postgres-dev, localhost:5432)
.venv/bin/uvicorn app.main:app --reload   # dev server; Swagger at http://localhost:8000/docs
.venv/bin/pytest                      # tests (needs the local Postgres container running)
.venv/bin/ruff check . && .venv/bin/ruff format --check .   # lint + format check
.venv/bin/ruff check --fix . && .venv/bin/ruff format .     # auto-fix
.venv/bin/alembic revision --autogenerate -m "describe change"
.venv/bin/alembic upgrade head
```

## Layout

```
app/
├── main.py                 FastAPI app; registers error handlers and routers
├── core/config.py          pydantic-settings Settings, read from env / .env
├── core/exceptions.py      AppError hierarchy (status_code + code + message)
├── core/error_handlers.py  maps every error to {"error": {"code", "message", "details?"}}
├── db/base.py              DeclarativeBase
├── db/session.py           engine, SessionLocal, get_db() dependency
├── models/                 SQLAlchemy models; each must be imported in models/__init__.py
├── schemas/                Pydantic request/response models (Create / Update / Read per resource)
└── api/routes/             one APIRouter per resource
alembic/                    env.py reads DATABASE_URL from settings; versions/ holds migrations
tests/                      pytest; conftest.py provides engine / db_session / client fixtures
```

Adding a resource: model → import it in `models/__init__.py` (otherwise Alembic autogenerate won't see it) → `alembic revision --autogenerate` and review the generated file → schemas → router → `app.include_router` in `main.py` → `tests/test_<resource>.py`.

## Conventions

- Route handlers are plain `def`, not `async def`: psycopg2 is a blocking driver, and FastAPI runs sync handlers in a threadpool. Only switch to `async def` together with an async driver.
- Raise `AppError` subclasses (e.g. `NotFoundError`) from routes, never `HTTPException`, so responses keep the shared error envelope. Add a new error by subclassing `AppError` with `status_code`/`code`/`message`; no handler changes needed.
- Validation errors return 422 with `code: "VALIDATION_ERROR"` and `details: [{field, message}]`. Unhandled exceptions return a generic 500 body; the traceback only goes to the server log.
- PATCH uses `model_dump(exclude_unset=True)` so only sent fields change. Non-nullable columns need a validator on the Update schema to reject explicit `null` (see `ItemUpdate.name_not_null`).
- Timestamps are `DateTime(timezone=True)` (`timestamptz`). `updated_at` relies on SQLAlchemy `onupdate`, so it does not change when rows are edited directly in the DB.

## Database

- Local dev: `docker-compose.yml` runs `postgres:16` as `app-postgres-dev` on `localhost:5432` (user/password/db: `app`/`devpassword`/`app`). Fine to expose locally; the production DB on EC2 binds to `127.0.0.1` only and is reached through an SSH tunnel.
- Schema changes go through Alembic only — never alter tables by hand (DataGrip, psql), or the `alembic_version` history drifts from the real schema. Always read autogenerated migrations before applying; renames can come out as drop + add.
- `alembic.ini` intentionally leaves `sqlalchemy.url` empty; `alembic/env.py` injects `settings.database_url`.

## Environment variables

- `DATABASE_URL` (required) — `postgresql+psycopg2://user:pass@host:port/db`. Copy `.env.example` to `.env` for local dev. pydantic-settings rejects unknown keys in `.env`, so only add keys that exist on `Settings`.
- `TEST_DATABASE_URL` (optional, tests only) — defaults to the `app_test` DB on the local container. `tests/conftest.py` creates it if missing and refuses to run unless the DB name ends in `_test`, because it drops and recreates tables.

## Tests

- Each test runs inside a transaction that is rolled back afterwards (`join_transaction_mode="create_savepoint"`), so tests start from empty tables and are order-independent. App commits become savepoints.
- `client` overrides the `get_db` dependency with the test session; route code is untouched.
- CI (`.github/workflows/ci.yml`) runs ruff, `alembic upgrade head` on a fresh Postgres service, then pytest.
